# ContextSentry

ContextSentry is a Python CLI and Model Context Protocol (MCP) server that routes file reads through a context gate. Small, low-complexity files can be returned in full; files that exceed configured size or Python complexity thresholds are summarized by a secondary model so the primary coding assistant receives a smaller response.

The repository currently implements an **opt-in gate**: callers must use the CLI or the MCP `intercept_read_file` tool. It does not automatically intercept every IDE or agent file read, and it is not itself a registered PreToolUse hook for Claude Code, Codex, or other clients.

## What it does

- **Dual-threshold gate:** defaults to gating files over 350 lines or Python files with a calculated cyclomatic complexity above 15. The thresholds can be set when constructing `PreToolUseHook` in code.
- **Worker summary:** `BulkReadWorker` sends the file and a focused query to Ollama's `/api/generate` endpoint, defaulting to `llama3.2` at `http://localhost:11434`.
- **Symbol indexing:** for gated Python files, the gate can extract class and function names with line ranges.
- **Secret-pattern detection:** the gate scans for selected credential-like strings, JWTs, IPv4 addresses, and private keys while evaluating a file.
- **Direct-to-disk generation:** the `write` CLI command and MCP `intercept_write_file` tool ask the local worker to generate Python code and write it to disk.
- **SQLite telemetry:** read interceptions record pass/block counts and estimated token and dollar savings. A separate benchmark table records estimated raw/injected tokens, latency, redaction count, and complexity.

## Important implementation notes

- Complexity analysis uses Python's AST. For non-Python or syntactically invalid input, the evaluator falls back to complexity 1, so those files are gated by line count only.
- Secret detection is currently used during gate evaluation and symbol indexing. The worker reader independently reopens and sends the original file contents to Ollama, so the current flow does **not** guarantee that detected secrets are removed before the worker request.
- The gate's `inspect_file_read` method returns a pass/block decision; the CLI and MCP server invoke the worker to produce the actual summary. The gated response is therefore not generated by that method itself.
- Telemetry estimates savings as 10 tokens per blocked line and applies a fixed $2.50 per million token rate. These are rough estimates, not measured tokenizer counts or realized cost reductions.
- Ollama is the only worker backend currently implemented. The README makes no claim of a configured Azure/EY endpoint.

## Requirements

- Python 3.10 or newer
- Ollama, with the `llama3.2` model available locally, for worker summaries and generated files

Install the Python dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Start Ollama separately and pull the default model if needed:

```bash
ollama pull llama3.2
```

The gate and telemetry can be used without a reachable Ollama service, but worker calls then return a fallback error message instead of a generated summary or file.

## CLI

Read a file through the gate. Files that pass are printed in full; gated files are sent to the worker with the supplied query:

```bash
python main.py read path/to/file.py
python main.py read path/to/file.py --query "List the key classes and how they interact"
```

Generate a Python file directly to disk:

```bash
python main.py write path/to/output.py --prompt "Create a small command-line parser"
```

View interception telemetry:

```bash
python main.py stats
```

## MCP server

Run the server over stdio:

```bash
python mcp_server.py
```

The server exposes these tools:

| Tool | Purpose |
| --- | --- |
| `intercept_read_file(file_path, query)` | Gate a file read, return small files directly, or return a worker summary for gated files. |
| `intercept_write_file(target_path, specification)` | Generate Python code through the worker and write it to the target path. |
| `get_telemetry_stats()` | Return aggregate read and estimated savings metrics. |

Configure your MCP client to launch `python mcp_server.py` with this repository as its working directory. Client configuration varies; this server does not install or enable itself in an agent automatically.

## Repository map

```text
main.py                 Typer CLI (`read`, `write`, `stats`)
mcp_server.py           stdio MCP server and tool definitions
core/hook.py            Gate orchestration and benchmark logging
core/evaluator.py       Line-count and Python complexity evaluation
core/security.py        Pattern-based secret detection/redaction
core/symbol_indexer.py  Python class/function index with line ranges
core/worker_reader.py   Ollama-backed file summarization
core/worker_writer.py   Ollama-backed code generation to disk
core/monitor.py         SQLite interception telemetry
core/benchmark.py       SQLite benchmark telemetry
tests/                  Pipeline tests
*_demo.py               Example/demo source files
benchmark_report.py     Telemetry report script
```

Runtime telemetry is written to `data/contextsentry.db` relative to the current working directory.

## Tests

Run the pipeline tests with:

```bash
pytest
```

The large-file test calls the configured Ollama service, so Ollama must be running with the selected model for that test to pass without its fallback assertion failing.
